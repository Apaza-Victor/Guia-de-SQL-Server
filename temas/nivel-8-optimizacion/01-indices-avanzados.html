Índices Avanzados

Más allá de los índices clustered y nonclustered básicos, SQL Server ofrece tipos especializados que pueden mejorar drásticamente el rendimiento en escenarios específicos.

Tipos de Índices Avanzados

Tipo de ÍndiceUso principalEjemplo
FiltradoIndexar solo un subconjunto de filasWHERE activo = 1
Columnas incluidasEvitar bookmark lookup (cubrir consultas)INCLUDE (nombre, email)
ColumnstoreData warehousing, agregaciones masivasAlmacenamiento columnar
Clustered ColumnstoreTablas de gran volumen (UPDATE/ DELETE limitados)Tablas de hechos

Índice Filtrado

T-SQL
CREATE NONCLUSTERED INDEX idx_clientes_activos
ON clientes(email)
WHERE activo = 1;  -- Solo indexa clientes activos

-- Más pequeño y rápido que un índice completo

Columnas Incluidas

T-SQL
CREATE INDEX idx_ventas_fecha
ON ventas(fecha)
INCLUDE (total, id_cliente, impuesto);
-- La consulta se satisface completamente desde el índice (covering)

Columnstore Index

T-SQL
-- Tabla de hechos para análisis
CREATE TABLE ventas_historicas (
    id_venta BIGINT,
    fecha DATE,
    id_producto INT,
    cantidad INT,
    total DECIMAL(18,2)
);

CREATE CLUSTERED COLUMNSTORE INDEX cci_ventas
ON ventas_historicas;

Los índices columnstore almacenan datos por columnas en lugar de filas, logrando compresiones 5-10x y acelerando consultas analíticas que agregan grandes volúmenes.

Mantenimiento de Índices

Con el tiempo, los índices se fragmentan. La fragmentación ocurre cuando las páginas de datos pierden orden físico.

T-SQL
-- Ver fragmentación
SELECT
    s.name AS schema_name,
    t.name AS table_name,
    i.name AS index_name,
    ips.avg_fragmentation_in_percent,
    ips.page_count
FROM sys.dm_db_index_physical_stats(
    DB_ID(), NULL, NULL, NULL, 'LIMITED') ips
JOIN sys.indexes i ON ips.object_id = i.object_id AND ips.index_id = i.index_id
JOIN sys.tables t ON i.object_id = t.object_id
JOIN sys.schemas s ON t.schema_id = s.schema_id
ORDER BY ips.avg_fragmentation_in_percent DESC;

-- REORGANIZE (fragmentación 5-30%)
ALTER INDEX idx_clientes_activos ON clientes REORGANIZE;

-- REBUILD (fragmentación > 30%)
ALTER INDEX idx_clientes_activos ON clientes REBUILD;
ALTER INDEX ALL ON clientes REBUILD;  -- Todos los índices de la tabla
Fragmentación

La fragmentación alta (>30%) degrada el rendimiento de las consultas. Sin embargo, no todos los índices requieren mantenimiento diario. Monitorea la fragmentación semanalmente y programa REBUILD/REORGANIZE en ventanas de mantenimiento. REBUILD es una operación intensiva que bloquea la tabla; considera ONLINE = ON (Solo Enterprise) para minimizar la indisponibilidad.

Index Usage Stats

T-SQL
-- Índices no usados (candidatos a eliminar)
SELECT
    OBJECT_NAME(i.object_id) AS tabla,
    i.name AS indice,
    s.user_seeks + s.user_scans + s.user_lookups AS lecturas,
    s.user_updates AS escrituras
FROM sys.dm_db_index_usage_stats s
JOIN sys.indexes i ON s.object_id = i.object_id AND s.index_id = i.index_id
WHERE s.database_id = DB_ID()
ORDER BY lecturas ASC;
