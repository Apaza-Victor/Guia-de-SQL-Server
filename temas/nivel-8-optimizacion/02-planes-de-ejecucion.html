Planes de Ejecución

El plan de ejecución muestra cómo SQL Server ejecuta una consulta: qué índices usa, cómo combina tablas y qué operaciones realiza. Leer planes es la habilidad más importante para la optimización.

Plan Estimado vs Plan Real

  • Plan estimado: Muestra el plan que el optimizador calcula sin ejecutar la consulta. Se obtiene con SET SHOWPLAN_XML ON o el botón "Display Estimated Execution Plan".
  • Plan real: Incluye métricas reales (filas devueltas, tiempo por operador). Se obtiene con SET STATISTICS XML ON o "Include Actual Execution Plan".
T-SQL
-- Plan estimado (no ejecuta)
SET SHOWPLAN_XML ON;
SELECT * FROM clientes WHERE ciudad = 'Bogotá';
SET SHOWPLAN_XML OFF;

-- Plan real con estadísticas
SET STATISTICS TIME ON;
SET STATISTICS IO ON;
SET STATISTICS XML ON;
SELECT * FROM clientes WHERE ciudad = 'Bogotá';
SET STATISTICS TIME OFF;
SET STATISTICS IO OFF;
SET STATISTICS XML OFF;

Operadores Comunes

OperadorSignificadoCuándo es bueno/malo
Clustered Index ScanRecorre toda la tabla (o índice clustered)Malo si la tabla es grande y devuelve pocas filas; inevitable si devuelve muchas
Clustered Index SeekBusca directamente por clave del índiceExcelente, acceso rápido a filas específicas
Nonclustered Index Seek + Key LookupBusca en índice no clúster + recupera datos del clústerAceptable, pero muchos lookups indican que faltan columnas incluidas
Nested LoopsPara cada fila de una tabla, busca filas en la otraBueno si una tabla es pequeña o el join está muy filtrado
Hash MatchConstruye una tabla hash en memoria para el joinBueno para joins grandes sin índices adecuados
Merge JoinJoin ordenado (requiere datos ordenados)Excelente para conjuntos grandes ya ordenados
SortOrdena datos (por ORDER BY, GROUP BY, Merge Join)Costoso; evitar si se puede indexar el orden
Spool (Eager/Lazy)Almacena resultados intermediosA veces necesario; excesivo puede indicar plan subóptimo
Table ScanRecorre toda la tabla (heap sin índice)Generalmente malo — tabla sin índice clúster

Identificar Operaciones Costosas

T-SQL
SET STATISTICS TIME ON;
SET STATISTICS IO ON;

SELECT c.nombre, COUNT(p.id_pedido) AS total_pedidos
FROM clientes c
LEFT JOIN pedidos p ON c.id_cliente = p.id_cliente
WHERE c.ciudad = 'Medellín'
GROUP BY c.nombre
ORDER BY total_pedidos DESC;

SET STATISTICS IO OFF;
SET STATISTICS TIME OFF;

La salida de STATISTICS IO muestra lecturas lógicas (page lookups) y físicas. Menos lecturas = mejor rendimiento. STATISTICS TIME muestra tiempos de CPU y elapsed.

Usa SSMS para planes gráficos

SQL Server Management Studio (SSMS) muestra planes de ejecución gráficos que facilitan identificar operadores costosos (el grosor de las flechas indica volumen de filas, el color rojo indica advertencias). Pasa el mouse sobre cada operador para ver costo relativo, filas estimadas vs reales y otras métricas. Para análisis avanzado, usa Plan Explorer (gratuito) de SolarWinds.

Plan Cache

T-SQL
-- Consultar planes en caché
SELECT
    qs.total_worker_time / qs.execution_count AS avg_cpu,
    qs.total_logical_reads / qs.execution_count AS avg_reads,
    SUBSTRING(st.text, qs.statement_start_offset/2 + 1,
        (CASE WHEN qs.statement_end_offset = -1
            THEN LEN(CONVERT(NVARCHAR(MAX), st.text)) * 2
            ELSE qs.statement_end_offset - qs.statement_start_offset
        END) / 2) AS query_text,
    qp.query_plan
FROM sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) st
CROSS APPLY sys.dm_exec_query_plan(qs.plan_handle) qp
ORDER BY avg_cpu DESC;
