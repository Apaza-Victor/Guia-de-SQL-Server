Arquitectura de SQL Server

Arquitectura cliente-servidor

SQL Server sigue una arquitectura cliente-servidor. El servidor (motor de base de datos) se ejecuta como un servicio de Windows y acepta conexiones de múltiples clientes simultáneamente. Los clientes envían consultas T-SQL y el servidor devuelve los resultados.

Componentes de SQL Server

ComponenteFunción
Database EngineMotor principal: almacena, procesa y asegura los datos. Incluye el Query Processor y Storage Engine.
SSAS (Analysis Services)Servicio de análisis y minería de datos. Crea cubos OLAP y modelos tabulares.
SSIS (Integration Services)Plataforma de integración y ETL (Extraer, Transformar, Cargar).
SSRS (Reporting Services)Plataforma de informes y reportes empresariales.
SQL Server AgentProgramador de trabajos y tareas automatizadas.
Full-Text SearchMotor de búsqueda de texto completo en documentos y columnas.

Cómo procesa SQL Server una consulta

  1. Conexión — el cliente establece una conexión TCP/IP con el servidor.
  2. Recepción — el servidor recibe la consulta T-SQL.
  3. Análisis (Parsing) — el Query Processor analiza la sintaxis y genera un árbol lógico.
  4. Compilación — el optimizador de consultas genera un plan de ejecución.
  5. Ejecución — el Storage Engine ejecuta el plan, accediendo a los datos en disco o caché.
  6. Resultados — los datos se devuelven al cliente.
Nota

SQL Server utiliza un protocolo de capa de aplicación llamado TDS (Tabular Data Stream) para la comunicación entre cliente y servidor. Este protocolo está optimizado para el envío eficiente de resultados tabulares.
