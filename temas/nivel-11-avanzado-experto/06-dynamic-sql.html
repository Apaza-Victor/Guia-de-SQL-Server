Dynamic SQL

Dynamic SQL consiste en construir y ejecutar sentencias SQL dinámicamente en tiempo de ejecución. Es útil cuando la estructura de la consulta no se conoce hasta la ejecución, como nombres de tabla variables o condiciones generadas por el usuario.

SQL Injection

El mayor riesgo de Dynamic SQL es la inyección SQL. Nunca concatenes valores directamente. Usa siempre parámetros (sp_executesql) y QUOTENAME() para nombres de objetos.

sp_executesql vs EXEC()

Característicasp_executesqlEXEC()
ParametrizaciónSí (con parámetros tipados)No (solo concatenación)
Plan cacheReutiliza planes (mismo template)No reutiliza (cada ejecución es única)
Protección SQL InjectionAlta (con parámetros)Nula (concatenación)
LegibilidadBuenaSimple para scripts pequeños
RecomendadoSiempre que sea posibleSolo para scripts ad-hoc

Ejemplo: sp_executesql con Parámetros

T-SQL
DECLARE @sql NVARCHAR(MAX);
DECLARE @paramDef NVARCHAR(MAX);
DECLARE @status INT = 1;
DECLARE @minTotal DECIMAL(10,2) = 1000;

SET @sql = N'
    SELECT OrderID, CustomerName, Total
    FROM Orders
    WHERE Status = @Status
      AND Total >= @MinTotal
    ORDER BY Total DESC;
';

SET @paramDef = N'@Status INT, @MinTotal DECIMAL(10,2)';

EXEC sp_executesql @sql,
    @paramDef,
    @Status = @status,
    @MinTotal = @minTotal;

QUOTENAME para Nombres de Objetos

Cuando necesitas usar nombres de tablas o columnas dinámicamente, QUOTENAME() los envuelve entre corchetes de forma segura.

T-SQL
DECLARE @tabla NVARCHAR(128) = 'Orders';
DECLARE @sql NVARCHAR(MAX);

-- SEGURO: QUOTENAME evita inyección
SET @sql = N'SELECT * FROM ' + QUOTENAME(@tabla);

-- INSEGURO: concatenación directa
-- SET @sql = N'SELECT * FROM ' + @tabla;  -- !!! PELIGRO

EXEC sp_executesql @sql;

Ejemplo: Búsqueda Dinámica Segura

T-SQL
CREATE PROCEDURE dbo.BuscarProductos
    @Nombre     NVARCHAR(100) = NULL,
    @Categoria  INT           = NULL,
    @PrecioMin  DECIMAL(10,2) = NULL,
    @PrecioMax  DECIMAL(10,2) = NULL
AS
BEGIN
    DECLARE @sql NVARCHAR(MAX) = N'
        SELECT ProductID, Name, Price, CategoryID
        FROM Products
        WHERE 1=1';

    DECLARE @params NVARCHAR(MAX) = N'
        @Nombre    NVARCHAR(100),
        @Categoria INT,
        @PrecioMin DECIMAL(10,2),
        @PrecioMax DECIMAL(10,2)';

    IF @Nombre IS NOT NULL
        SET @sql += N' AND Name LIKE ''%'' + @Nombre + ''%''';

    IF @Categoria IS NOT NULL
        SET @sql += N' AND CategoryID = @Categoria';

    IF @PrecioMin IS NOT NULL
        SET @sql += N' AND Price >= @PrecioMin';

    IF @PrecioMax IS NOT NULL
        SET @sql += N' AND Price <= @PrecioMax';

    EXEC sp_executesql @sql, @params,
        @Nombre, @Categoria, @PrecioMin, @PrecioMax;
END;

Cuándo usar Dynamic SQL

  • Búsquedas con filtros opcionales (search builders)
  • Nombres de tabla/columna dinámicos (p. ej. tablas por año)
  • Generación dinámica de PIVOT / UNPIVOT
  • Scripts de administración que recorren bases de datos
/* --- Prefiere siempre SQL estático --- */

Si puedes escribir una consulta fija sin Dynamic SQL, hazlo. El Dynamic SQL solo debe usarse cuando no hay alternativa.
