Modelado entidad-relación

El modelo entidad-relación (ER) es una técnica de diseño conceptual de bases de datos que representa las entidades del mundo real y las relaciones entre ellas.

Conceptos fundamentales

Entidad

Objeto del mundo real distinguible de otros. Se representa como un rectángulo. Ejemplos: Cliente, Producto, Pedido.

Atributo

Propiedades que describen una entidad. Ejemplos: Nombre, Email, Precio. La clave primaria se subraya.

Relación

Asociación entre dos o más entidades. Se representa como un rombo. Tiene una cardinalidad que define cuántas instancias se relacionan.

CardinalidadNotación Crow's FootSignificado
Uno a uno (1:1)—||—||—Un cliente tiene una dirección; una dirección pertenece a un cliente
Uno a muchos (1:N)—||—<—Un cliente tiene muchos pedidos; un pedido pertenece a un cliente
Muchos a muchos (N:M)—>—<—Un producto está en muchos pedidos; un pedido tiene muchos productos

De ER a SQL

T-SQL 
CREATE TABLE Cliente (
    ClienteID INT IDENTITY(1,1) PRIMARY KEY,
    Nombre NVARCHAR(100) NOT NULL,
    Email NVARCHAR(200) NOT NULL UNIQUE
);

CREATE TABLE Pedido (
    PedidoID INT IDENTITY(1,1) PRIMARY KEY,
    FechaPedido DATETIME2 DEFAULT GETDATE(),
    ClienteID INT NOT NULL,
    CONSTRAINT FK_Pedido_Cliente
        FOREIGN KEY (ClienteID) REFERENCES Cliente(ClienteID)
);

CREATE TABLE Producto (
    ProductoID INT IDENTITY(1,1) PRIMARY KEY,
    Nombre NVARCHAR(100) NOT NULL,
    Precio DECIMAL(10,2) NOT NULL
);

-- Tabla para relación N:M
CREATE TABLE PedidoProducto (
    PedidoID INT NOT NULL,
    ProductoID INT NOT NULL,
    Cantidad INT NOT NULL DEFAULT 1,
    CONSTRAINT PK_PedidoProducto PRIMARY KEY (PedidoID, ProductoID),
    CONSTRAINT FK_PP_Pedido FOREIGN KEY (PedidoID) REFERENCES Pedido(PedidoID),
    CONSTRAINT FK_PP_Producto FOREIGN KEY (ProductoID) REFERENCES Producto(ProductoID)
);
Tip

Para diseñar diagramas ER, puedes usar herramientas como dbdiagram.io, draw.io o MySQL Workbench. También existen extensiones en VS Code para modelado ER.
