Claves y relaciones

Las claves y restricciones garantizan la integridad y consistencia de los datos en una base de datos relacional.

Primary Key (Clave primaria)

Identifica de forma única cada fila de una tabla. No permite NULL y debe ser única.

T-SQL 
-- Como restricción de columna
CREATE TABLE Clientes (
    ClienteID INT IDENTITY(1,1) PRIMARY KEY,
    Nombre NVARCHAR(100) NOT NULL
);

-- Como restricción de tabla (permite clave compuesta)
CREATE TABLE PedidoProducto (
    PedidoID INT NOT NULL,
    ProductoID INT NOT NULL,
    Cantidad INT NOT NULL,
    CONSTRAINT PK_PedidoProducto PRIMARY KEY (PedidoID, ProductoID)
);

-- Agregar PK a tabla existente
ALTER TABLE Clientes
ADD CONSTRAINT PK_Clientes PRIMARY KEY (ClienteID);

Foreign Key (Clave foránea)

Establece una relación entre dos tablas. Garantiza que los valores en una columna existan en la tabla referenciada.

T-SQL 
CREATE TABLE Pedidos (
    PedidoID INT IDENTITY(1,1) PRIMARY KEY,
    ClienteID INT NOT NULL,
    Fecha DATE DEFAULT GETDATE(),
    CONSTRAINT FK_Pedidos_Clientes
        FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID)
);

-- FK con nombre explícito en tabla existente
ALTER TABLE Pedidos
ADD CONSTRAINT FK_Pedidos_Clientes
FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID);

Unique Constraint

Garantiza que todos los valores en una columna (o combinación) sean únicos. A diferencia de PK, permite un NULL (en SQL Server solo un NULL).

T-SQL 
CREATE TABLE Usuarios (
    UsuarioID INT IDENTITY(1,1) PRIMARY KEY,
    Email NVARCHAR(200) NOT NULL,
    NombreUsuario NVARCHAR(50) NOT NULL,
    CONSTRAINT UQ_Usuarios_Email UNIQUE (Email),
    CONSTRAINT UQ_Usuarios_Nombre UNIQUE (NombreUsuario)
);

Check Constraint

Valida que los datos cumplan una condición específica.

T-SQL 
CREATE TABLE Productos (
    ProductoID INT IDENTITY(1,1) PRIMARY KEY,
    Nombre NVARCHAR(100) NOT NULL,
    Precio DECIMAL(10,2) NOT NULL,
    Stock INT NOT NULL DEFAULT 0,
    CONSTRAINT CK_Precio_Positivo CHECK (Precio > 0),
    CONSTRAINT CK_Stock_No_Negativo CHECK (Stock >= 0)
);

-- CHECK con condición compleja
ALTER TABLE Pedidos
ADD CONSTRAINT CK_Fecha_Valida
CHECK (Fecha >= '2020-01-01');

Integridad referencial y ON DELETE

Define qué sucede con las filas hijas cuando se elimina la fila padre.

T-SQL 
-- NO ACTION (predeterminado): error si hay filas hijas
FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID)
-- ON DELETE NO ACTION -- implícito

-- CASCADE: elimina automáticamente las filas hijas
FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID)
ON DELETE CASCADE;

-- SET NULL: establece NULL en las filas hijas
FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID)
ON DELETE SET NULL;

-- SET DEFAULT: establece el valor por defecto
FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID)
ON DELETE SET DEFAULT;
Peligro

Los errores de integridad referencial ocurren cuando intentas insertar un valor FK que no existe en la tabla padre, o eliminar un padre que tiene hijos. Planifica bien el uso de ON DELETE CASCADE para evitar borrados accidentales en cascada.
