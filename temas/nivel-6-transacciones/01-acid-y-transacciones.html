ACID y Transacciones

Una transacción es una unidad lógica de trabajo que consta de una o más operaciones sobre la base de datos. SQL Server garantiza la integridad de las transacciones mediante las propiedades ACID.

Propiedades ACID

PropiedadSignificadoImplementación en SQL Server
AtomicityTodo o nada: la transacción se completa completamente o no se aplica ningún cambioCOMMIT confirma; ROLLBACK deshace todas las operaciones
ConsistencyLa base de datos pasa de un estado válido a otro estado válidoRestricciones, reglas, triggers, integridad referencial
IsolationLas transacciones concurrentes no interfieren entre síNiveles de aislamiento y bloqueos
DurabilityUna vez confirmado, el cambio persiste ante fallosTransaction Log (WAL — Write-Ahead Logging)

Transacciones Explícitas

T-SQL
BEGIN TRANSACTION;
    UPDATE cuentas SET saldo = saldo - 100 WHERE id_cuenta = 1;
    UPDATE cuentas SET saldo = saldo + 100 WHERE id_cuenta = 2;
COMMIT TRANSACTION;
-- Ambas operaciones se confirman juntas

ROLLBACK y Savepoints

T-SQL
BEGIN TRAN;
    INSERT INTO log (mensaje) VALUES ('Paso 1');

    SAVE TRANSACTION punto_control;

    INSERT INTO log (mensaje) VALUES ('Paso 2');
    -- Si algo falla, podemos revertir solo hasta el savepoint
    ROLLBACK TRANSACTION punto_control;
    -- 'Paso 2' se deshace, 'Paso 1' permanece

COMMIT TRAN;

@@TRANCOUNT

Esta función devuelve el nivel de anidamiento de transacciones actual. Cada BEGIN TRAN incrementa el contador; cada COMMIT lo decrementa. ROLLBACK lo lleva a 0.

T-SQL
PRINT @@TRANCOUNT;  -- 0
BEGIN TRAN;
    PRINT @@TRANCOUNT;  -- 1
    BEGIN TRAN;
        PRINT @@TRANCOUNT;  -- 2
    COMMIT;
    PRINT @@TRANCOUNT;  -- 1
COMMIT;
PRINT @@TRANCOUNT;  -- 0

Transacciones Implícitas

Cuando SET IMPLICIT_TRANSACTIONS ON, SQL Server inicia automáticamente una transacción para cada instrucción DDL/DML, pero requiere COMMIT o ROLLBACK explícito.

Transacciones abiertas

Siempre verifica que no haya transacciones abiertas sin confirmar (ROLLBACK o COMMIT). Una transacción abierta mantiene bloqueos y puede causar deadlocks o crecimiento excesivo del log de transacciones. Usa DBCC OPENTRAN para identificar transacciones huérfanas.
