Niveles de Aislamiento

Los niveles de aislamiento determinan cómo las transacciones se relacionan entre sí al acceder a los mismos datos. Controlan el equilibrio entre consistencia y concurrencia.

Fenómenos de Lectura

  • Dirty Read: Leer datos modificados por otra transacción aún no confirmada. Si esa transacción se deshace, los datos leídos son inválidos.
  • Non-repeatable Read: Dentro de una transacción, una misma consulta devuelve diferentes valores porque otra transacción modificó y confirmó los datos entre ambas lecturas.
  • Phantom Read: Dentro de una transacción, una misma consulta devuelve filas adicionales porque otra transacción insertó filas que coinciden con el filtro.

Configuración

T-SQL
-- A nivel de sesión
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;

-- SNAPSHOT requiere habilitar la BD
ALTER DATABASE MiBD SET ALLOW_SNAPSHOT_ISOLATION ON;
SET TRANSACTION ISOLATION LEVEL SNAPSHOT;

Ejemplo: Dirty Read

T-SQL
-- Sesión 1
BEGIN TRAN;
    UPDATE productos SET precio = 9999 WHERE id = 1;
    -- Sin COMMIT aún

-- Sesión 2 (con READ UNCOMMITTED)
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SELECT precio FROM productos WHERE id = 1;  -- Devuelve 9999 aunque no esté confirmado

-- Sesión 1: ROLLBACK;  -- El dato leído era inválido

Ejemplo: SERIALIZABLE evita Phantom Reads

T-SQL
-- Sesión 1
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
BEGIN TRAN;
    SELECT COUNT(*) FROM productos WHERE precio > 100;
    -- Sesión 2 no puede insertar filas que cumplan la condición hasta que termine
COMMIT;
Elegir el nivel adecuado

READ COMMITTED es el nivel predeterminado y funciona bien para la mayoría de aplicaciones. Usa READ UNCOMMITTED solo para reportes donde la exactitud no sea crítica. SERIALIZABLE garantiza consistencia total pero reduce la concurrencia. SNAPSHOT ofrece consistencia sin bloqueos de lectura, a costa de mayor uso de tempdb.
