Bloqueos y Deadlocks

SQL Server usa bloqueos para garantizar la consistencia y el aislamiento entre transacciones concurrentes. Entender los tipos de bloqueo y cómo prevenir deadlocks es esencial para administrar bases de datos con alta concurrencia.

Tipos de Bloqueo

BloqueoAbrev.Descripción
Shared (Lectura)SPermite leer, pero no modificar. Varias transacciones pueden tenerlo simultáneamente
Exclusive (Escritura)XPermite leer y modificar. Solo una transacción lo posee. Nadie más puede leerlo ni modificarlo
UpdateUFase previa a la escritura. Evita deadlocks entre lecturas que luego serán escrituras
IntentIS, IX, SIXIndica intención de adquirir bloqueo a nivel más fino (fila → página → tabla)
SchemaSch-M, Sch-SProtege definiciones de objetos (DDL) y consultas dependientes
Bulk UpdateBUUsado en operaciones bulk insert

Granularidad de Bloqueos

SQL Server puede bloquear a distintos niveles: fila (row), página (8 KB), extensión, tabla, partición o base de datos. El motor elige el nivel óptimo automáticamente según la cantidad de filas afectadas.

Deadlocks

Un deadlock ocurre cuando dos o más transacciones se bloquean mutuamente, cada una esperando que la otra libere un recurso. SQL Server detecta deadlocks automáticamente (mediante un hilo llamado deadlock monitor) y elige una víctima para terminar su transacción.

T-SQL
-- Generar un deadlock intencional

-- Sesión 1
BEGIN TRAN;
    UPDATE productos SET precio = 100 WHERE id_producto = 1;
    -- Ahora espera por Sesión 2...
    UPDATE inventario SET stock = 50 WHERE id_producto = 1;
COMMIT;

-- Sesión 2
BEGIN TRAN;
    UPDATE inventario SET stock = 30 WHERE id_producto = 1;
    -- Ahora espera por Sesión 1...
    UPDATE productos SET precio = 200 WHERE id_producto = 1;
COMMIT;

SQL Server terminará una de las transacciones con error 1205 y deshará sus cambios. La aplicación debe reintentar la transacción fallida.

Minimizando Deadlocks

  • Acceder a los recursos siempre en el mismo orden lógico.
  • Mantener las transacciones lo más cortas posible.
  • Usar índices adecuados para reducir la cantidad de bloqueos de fila/página.
  • Considerar el nivel de aislamiento READ COMMITTED SNAPSHOT para evitar bloqueos de lectura.
  • Dividir transacciones largas en lotes más pequeños.
Reintentar tras deadlock

Las aplicaciones deben capturar el error 1205 (deadlock victim) y reintentar la transacción. No asumas que un deadlock es una condición fatal; es un comportamiento esperado en sistemas con alta concurrencia. Implementa un bucle de reintento con un límite máximo (ej. 3-5 intentos) y un retardo exponencial.

Monitorear Bloqueos

T-SQL
-- Ver bloqueos actuales
SELECT * FROM sys.dm_tran_locks;

-- Ver sesiones bloqueadas
SELECT session_id, blocking_session_id, wait_type, wait_time
FROM sys.dm_exec_requests
WHERE blocking_session_id > 0;
