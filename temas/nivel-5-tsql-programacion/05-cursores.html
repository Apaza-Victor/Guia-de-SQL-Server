Cursores

Un cursor permite procesar filas una por una (row-by-row) en lugar de operar sobre conjuntos. SQL Server está optimizado para operaciones basadas en conjuntos, por lo que los cursores deben usarse solo cuando sea estrictamente necesario.

Rendimiento

Los cursores son significativamente más lentos que las operaciones set-based. Como regla general: si puedes resolverlo con una sola instrucción SQL, hazlo. Reserva los cursores para operaciones administrativas, migraciones de datos o lógica que requiera procesamiento secuencial (ej. recalcular saldos, enviar notificaciones individuales).

Ciclo de Vida de un Cursor

T-SQL
DECLARE @Id INT, @Nombre VARCHAR(100);

-- 1. DECLARE
DECLARE cursor_clientes CURSOR FOR
SELECT id_cliente, nombre FROM clientes WHERE activo = 1;

-- 2. OPEN
OPEN cursor_clientes;

-- 3. FETCH (primera fila)
FETCH NEXT FROM cursor_clientes INTO @Id, @Nombre;

WHILE @@FETCH_STATUS = 0
BEGIN
    PRINT CONCAT('Cliente ', @Id, ': ', @Nombre);

    -- 4. FETCH (siguientes filas)
    FETCH NEXT FROM cursor_clientes INTO @Id, @Nombre;
END;

-- 5. CLOSE
CLOSE cursor_clientes;

-- 6. DEALLOCATE (libera los recursos)
DEALLOCATE cursor_clientes;

Ejemplo con Cursor SCROLL

T-SQL
DECLARE cursor_scroll SCROLL CURSOR FOR
SELECT id_producto, nombre FROM productos;

OPEN cursor_scroll;

FETCH LAST FROM cursor_scroll;  -- Última fila
FETCH PRIOR FROM cursor_scroll; -- Fila anterior
FETCH FIRST FROM cursor_scroll; -- Primera fila
FETCH ABSOLUTE 5 FROM cursor_scroll; -- Fila 5
FETCH RELATIVE -2 FROM cursor_scroll; -- Dos filas atrás

CLOSE cursor_scroll;
DEALLOCATE cursor_scroll;

Cuándo (no) Usar Cursores

  • ✓ Usar: Tareas administrativas por fila, operaciones secuenciales complejas, migraciones que requieren lógica condicional imperativa.
  • ✗ Evitar: Cuando se puede reemplazar con consultas set-based, JOIN, UPDATE masivo, funciones de ventana, CTE recursivas.
