Procedimientos Almacenados

Un procedimiento almacenado (stored procedure) es un conjunto de instrucciones T-SQL precompiladas que se almacenan en el servidor. Proporcionan una capa de abstracción, seguridad y rendimiento sobre las operaciones de datos.

Creación de un Procedimiento Almacenado

T-SQL
CREATE PROCEDURE uspObtenerClientes
AS
BEGIN
    SELECT id_cliente, nombre, email FROM clientes
    WHERE activo = 1;
END;

Parámetros: IN y OUT

Los parámetros pueden ser de entrada (IN) o de salida (OUT). Por defecto son de entrada. Los de salida se declaran con OUTPUT.

T-SQL
-- Parámetros IN
CREATE PROCEDURE uspClientePorId
    @IdCliente INT
AS
    SELECT nombre, email, telefono
    FROM clientes WHERE id_cliente = @IdCliente;

-- Parámetros OUT
CREATE PROCEDURE uspContarClientesActivos
    @Total INT OUTPUT
AS
    SELECT @Total = COUNT(*) FROM clientes WHERE activo = 1;

-- Ejecución con OUTPUT
DECLARE @Cantidad INT;
EXEC uspContarClientesActivos @Total = @Cantidad OUTPUT;
PRINT @Cantidad;

Ejecutando Procedimientos

Se ejecutan con EXEC o EXECUTE. Se pueden omitir parámetros si tienen valores por defecto.

T-SQL
EXEC uspObtenerClientes;
EXEC uspClientePorId 42;
EXEC uspClientePorId @IdCliente = 42;  -- Explícito

-- Con valor por defecto
CREATE PROCEDURE uspProductosPorCategoria
    @CategoriaID INT = NULL
AS
    SELECT * FROM productos
    WHERE @CategoriaID IS NULL OR id_categoria = @CategoriaID;

EXEC uspProductosPorCategoria;  -- Todos los productos
EXEC uspProductosPorCategoria @CategoriaID = 5;

Valores de Retorno

Los procedimientos pueden devolver un entero (RETURN). Por convención, 0 indica éxito y valores distintos indican errores.

T-SQL
CREATE PROCEDURE uspEliminarProducto
    @Id INT
AS
    IF NOT EXISTS (SELECT 1 FROM productos WHERE id_producto = @Id)
        RETURN 404;  -- No encontrado

    DELETE FROM productos WHERE id_producto = @Id;
    RETURN 0;  -- Éxito

DECLARE @Resultado INT;
EXEC @Resultado = uspEliminarProducto 99;
IF @Resultado <> 0
    PRINT 'Error al eliminar';
Parámetros y seguridad

Usar siempre parámetros en lugar de concatenar cadenas en consultas dinámicas. Los parámetros se envían por separado y SQL Server los trata como datos, no como código ejecutable, previniendo la inyección SQL.

Beneficios

  • Reutilización: Una vez escrito, puede ejecutarse múltiples veces desde cualquier aplicación.
  • Seguridad: Se otorgan permisos sobre el SP sin exponer las tablas subyacentes.
  • Rendimiento: Los planes de ejecución se almacenan en caché, reduciendo compilación repetida.
  • Reducción de tráfico: Se envía solo el nombre y parámetros, no todo el código SQL.
  • Mantenibilidad: La lógica de negocio reside en el servidor; los cambios no requieren actualizar clientes.
