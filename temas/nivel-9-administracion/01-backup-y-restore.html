Backup y Restore

Las copias de seguridad son la línea de defensa más importante contra la pérdida de datos. SQL Server ofrece varios tipos de backup para adaptarse a diferentes RPO y RTO.

Diario] D1 --> L1[LOG BACKUP
Cada hora] L1 --> L2[LOG BACKUP
Cada hora] L2 --> L3[LOG BACKUP
Cada hora] L3 --> Rest[Restauración

Prueba tus restores

Un backup que no se puede restaurar no sirve. Programa pruebas periódicas de restore en un entorno aislado para verificar la integridad de tus copias.

Modelos de Recuperación

El modelo de recuperación determina cómo se gestionan los registros de transacciones:

ModeloUsoPérdida de datos
SIMPLEBases de datos de desarrollo o solo lecturaDesde el último backup FULL/DIFF
FULLBases de producción donde no se acepta pérdida de datosNinguna (si respaldas el log)
BULK_LOGGEDOperaciones masivas puntualesMínima (operaciones masivas no se recuperan punto a punto)

Tipos de Backup

TipoContenidoTamañoRestauración
FULLToda la base de datosGrandeBase completa
DIFFERENTIALCambios desde el último FULLMedioFULL + DIFF
TRANSACTION LOGTransacciones desde el último backup de logPequeñoFULL + DIFF + todos los LOGs

Comandos de Backup

T-SQL
-- FULL BACKUP
BACKUP DATABASE MiBase
TO DISK = 'C:\Backups\MiBase_FULL.bak'
WITH FORMAT, COMPRESSION, STATS = 10;

-- DIFFERENTIAL BACKUP
BACKUP DATABASE MiBase
TO DISK = 'C:\Backups\MiBase_DIFF.bak'
WITH DIFFERENTIAL, STATS = 10;

-- TRANSACTION LOG BACKUP
BACKUP LOG MiBase
TO DISK = 'C:\Backups\MiBase_LOG.trn'
WITH STATS = 10;
/* --- Estrategia de respaldo recomendada --- */

Para una base de producción se recomienda: FULL cada 24 h, DIFF cada 4-6 h, LOG cada 15-30 minutos (dependiendo del RPO).

Restore

La secuencia correcta para restaurar con recovery model FULL es: restaurar FULL, luego DIFF, y luego cada uno de los LOGs en orden cronológico.

T-SQL
-- Restaurar FULL backup
RESTORE DATABASE MiBase
FROM DISK = 'C:\Backups\MiBase_FULL.bak'
WITH NORECOVERY;

-- Restaurar DIFFERENTIAL (si existe)
RESTORE DATABASE MiBase
FROM DISK = 'C:\Backups\MiBase_DIFF.bak'
WITH NORECOVERY;

-- Restaurar LOGS en secuencia
RESTORE LOG MiBase
FROM DISK = 'C:\Backups\MiBase_LOG1.trn'
WITH NORECOVERY;

RESTORE LOG MiBase
FROM DISK = 'C:\Backups\MiBase_LOG2.trn'
WITH RECOVERY;  -- Último: WITH RECOVERY
WITH NORECOVERY vs WITH RECOVERY

Usa WITH NORECOVERY mientras aplicas backups diferenciales y logs. Solo el último restore debe usar WITH RECOVERY para dejar la base operativa.

Compresión y Cifrado

Desde SQL Server 2008 Enterprise, puedes comprimir backups para ahorrar espacio. SQL Server 2014+ permite cifrar backups con AES.

T-SQL
-- Backup comprimido y cifrado
BACKUP DATABASE MiBase
TO DISK = 'C:\Backups\MiBase_Encrypted.bak'
WITH COMPRESSION,
     ENCRYPTION (ALGORITHM = AES_256,
                 SERVER CERTIFICATE = MiCertificado);
Ubicación del backup

Nunca almacenes los backups en el mismo disco físico que la base de datos. Si el disco falla, pierdes todo. Usa almacenamiento externo, NAS, Azure Blob o AWS S3.
