Logins, Usuarios y Roles

SQL Server gestiona la seguridad en dos niveles: servidor (logins) y base de datos (usuarios). Un login proporciona acceso a la instancia; un usuario mapea ese login a una base de datos específica y le otorga permisos dentro de ella.

Logins (nivel servidor)

T-SQL
-- Login con autenticación SQL
CREATE LOGIN juan_perez WITH PASSWORD = 'Str0ng!Pass#';

-- Login con autenticación Windows
CREATE LOGIN [DOMINIO\jperez] FROM WINDOWS;

-- Ver logins existentes
SELECT name, type_desc FROM sys.sql_logins;

Usuarios (nivel base de datos)

T-SQL
USE MiBaseDeDatos;
CREATE USER juan_perez FOR LOGIN juan_perez;
CREATE USER [DOMINIO\jperez] FOR LOGIN [DOMINIO\jperez];

Roles — Fijos de Servidor

Rol fijo servidorPermisos principales
sysadminControl total sobre la instancia
serveradminConfigurar recursos del servidor
securityadminAdministrar logins y permisos
dbcreatorCrear y modificar bases de datos
processadminTerminar procesos (KILL)
setupadminAdministrar servidores vinculados
bulkadminEjecutar BULK INSERT
diskadminAdministrar archivos de disco
T-SQL
ALTER SERVER ROLE sysadmin ADD MEMBER juan_perez;
ALTER SERVER ROLE dbcreator ADD MEMBER [DOMINIO\jperez];

Roles — Fijos de Base de Datos

Rol fijo BDPermisos
db_ownerControl total sobre la BD
db_datareaderLeer todas las tablas
db_datawriterModificar todas las tablas
db_ddladminEjecutar DDL (CREATE, ALTER, DROP)
db_securityadminAdministrar roles y permisos en la BD
db_accessadminAdministrar usuarios de BD
db_backupoperatorRealizar backups
db_denydatareaderDenegar lectura de datos
db_denydatawriterDenegar escritura de datos
T-SQL
USE MiBaseDeDatos;
ALTER ROLE db_datareader ADD MEMBER juan_perez;
ALTER ROLE db_datawriter ADD MEMBER juan_perez;

Roles Personalizados

T-SQL
USE MiBaseDeDatos;
CREATE ROLE consultor_ventas;
GRANT SELECT ON schema::ventas TO consultor_ventas;
ALTER ROLE consultor_ventas ADD MEMBER juan_perez;

Bases de Datos Contenidas

Las bases de datos contenidas (containment) permiten autenticar usuarios directamente a nivel de BD sin un login en el servidor. Útil para migraciones y bases de datos autónomas.

T-SQL
ALTER DATABASE MiBD SET CONTAINMENT = PARTIAL;
USE MiBD;
CREATE USER ana_suarez WITH PASSWORD = 'Pass#123';
Windows Auth vs SQL Auth

La autenticación de Windows (integrada) es más segura porque usa el protocolo Kerberos, políticas de contraseñas del dominio y no expone credenciales en la cadena de conexión. La autenticación SQL (login/password) es útil para aplicaciones externas o cuando no hay dominio. Prefiere Windows Auth siempre que sea posible.
