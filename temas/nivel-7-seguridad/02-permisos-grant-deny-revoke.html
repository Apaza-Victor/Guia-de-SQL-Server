Permisos GRANT, DENY, REVOKE

SQL Server utiliza un sistema de permisos granular que permite controlar exactamente qué operaciones puede realizar cada usuario sobre cada objeto. Los permisos se administran con las instrucciones GRANT, DENY y REVOKE.

Instrucciones Fundamentales

T-SQL
-- GRANT: otorga un permiso
GRANT SELECT ON clientes TO juan_perez;
GRANT INSERT, UPDATE ON ventas TO rol_ventas;
GRANT SELECT ON schema::ventas TO rol_consultor;

-- DENY: deniega explícitamente un permiso (prevalece sobre GRANT)
DENY DELETE ON clientes TO juan_perez;
DENY SELECT ON tabla_sensible TO rol_ventas;

-- REVOKE: elimina un permiso previamente otorgado o denegado
REVOKE SELECT ON clientes FROM juan_perez;
REVOKE INSERT ON ventas FROM rol_ventas;

WITH GRANT OPTION

Permite que el usuario otorgue el mismo permiso a otros usuarios.

T-SQL
GRANT SELECT ON clientes TO juan_perez WITH GRANT OPTION;
-- Ahora juan_perez puede ejecutar:
-- GRANT SELECT ON clientes TO ana;

Jerarquía de Permisos

Los permisos se heredan desde el nivel superior al inferior:

Servidor → Base de Datos → Esquema → Objeto (tabla, vista, proc.)

Por ejemplo, GRANT SELECT ON schema::ventas TO usuario otorga SELECT sobre todas las tablas del esquema ventas.

Permisos Comunes

PermisoNivelDescripción
SELECTTabla, vista, columnaLeer datos
INSERTTabla, vistaInsertar filas
UPDATETabla, vista, columnaModificar datos
DELETETabla, vistaEliminar filas
EXECUTEProcedimiento almacenado, funciónEjecutar código
REFERENCESTabla, columnaCrear FK o CHECK que referencien el objeto
ALTERTabla, esquema, BDModificar la definición del objeto
CONTROLObjeto, BD, servidorControl total sobre el objeto (equivalente a db_owner)
VIEW DEFINITIONObjeto, BDVer metadatos del objeto

Permisos a Nivel de Columna

T-SQL
GRANT SELECT ON clientes(id_cliente, nombre, email) TO consultor_ventas;
DENY SELECT ON clientes(salario, evaluacion) TO consultor_ventas;
DENY prevalece sobre GRANT

En SQL Server, DENY siempre prevalece sobre GRANT, independientemente del orden en que se apliquen. Si un usuario pertenece a un rol que tiene GRANT y a otro rol que tiene DENY sobre el mismo permiso, el DENY gana. Esto incluye permisos heredados. Es la diferencia clave con REVOKE, que simplemente elimina un permiso sin negarlo explícitamente.

Ver Permisos Efectivos

T-SQL
SELECT * FROM fn_my_permissions('clientes', 'OBJECT');
SELECT * FROM fn_my_permissions(NULL, 'DATABASE');
SELECT * FROM fn_my_permissions(NULL, 'SERVER');
