Encriptación Básica

SQL Server ofrece múltiples mecanismos para proteger datos sensibles. Este tema cubre las opciones principales: encriptación transparente (TDE), encriptación a nivel de celda, hashing y Always Encrypted.

Encriptación a Nivel de Celda

Usa ENCRYPTBYPASSPHRASE y DECRYPTBYPASSPHRASE con una frase de contraseña.

T-SQL
-- Insertar datos encriptados
CREATE TABLE tarjetas (
    id INT PRIMARY KEY,
    titular VARCHAR(100),
    numero VARBINARY(256),  -- Encriptado
    cvv VARBINARY(64)       -- Encriptado
);

INSERT INTO tarjetas VALUES (
    1,
    'Juan Pérez',
    ENCRYPTBYPASSPHRASE('Clave$egura', '4111-1111-1111-1111'),
    ENCRYPTBYPASSPHRASE('Clave$egura', '123')
);

-- Leer datos desencriptados
SELECT
    id,
    titular,
    CAST(DECRYPTBYPASSPHRASE('Clave$egura', numero) AS VARCHAR(19)) AS numero,
    CAST(DECRYPTBYPASSPHRASE('Clave$egura', cvv) AS VARCHAR(4)) AS cvv
FROM tarjetas;

Hashing con HASHBYTES

El hash es unidireccional: no se puede revertir. Se usa para almacenar contraseñas o verificar integridad.

T-SQL
-- Algoritmos: MD2, MD4, MD5, SHA1, SHA2_256, SHA2_512
DECLARE @password VARCHAR(50) = 'MiClaveSegura';
DECLARE @hash VARBINARY(64);

SET @hash = HASHBYTES('SHA2_256', @password);
PRINT @hash;

-- Verificar contraseña
SELECT id_usuario FROM usuarios
WHERE hash_password = HASHBYTES('SHA2_256', 'IntentoDeClave');

Transparent Data Encryption (TDE)

TDE encripta automáticamente los archivos de datos (MDF, NDF, LDF) en reposo. Es transparente para las aplicaciones: no requieren cambios.

T-SQL
-- Crear clave maestra y certificado (una vez)
USE master;
CREATE MASTER KEY ENCRYPTION BY PASSWORD = 'ClaveMaestra123!';
CREATE CERTIFICATE CertTDE WITH SUBJECT = 'Certificado TDE';

-- Backup del certificado (¡OBLIGATORIO!)
BACKUP CERTIFICATE CertTDE
TO FILE = 'C:\SQL\CertTDE.cer'
WITH PRIVATE KEY (FILE = 'C:\SQL\CertTDE.pvk',
                  ENCRYPTION BY PASSWORD = 'ClavePrivada123!');

-- Habilitar TDE
USE MiBD;
CREATE DATABASE ENCRYPTION KEY
WITH ALGORITHM = AES_256
ENCRYPTION BY SERVER CERTIFICATE CertTDE;
ALTER DATABASE MiBD SET ENCRYPTION ON;

Always Encrypted

Encripta columnas a nivel de aplicación. El servidor nunca ve los datos desencriptados. Requiere usar el driver .NET 4.6+ o JDBC y especificar Column Encryption Setting=Enabled en la cadena de conexión.

Gestión de claves

La seguridad de la encriptación depende de la protección de las claves. Realiza siempre un backup del certificado y la clave maestra. Sin ellos, los datos encriptados son irrecuperables. Para TDE, guarda el certificado y la clave privada en un lugar seguro fuera del servidor. Para Always Encrypted, las claves residen en el cliente (Azure Key Vault o Windows Certificate Store).
