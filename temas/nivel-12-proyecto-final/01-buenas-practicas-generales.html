Buenas Prácticas Generales

Escribir código SQL limpio, consistente y mantenible es tan importante como la funcionalidad. Estas buenas prácticas te ayudarán a trabajar en equipo y a mantener bases de datos saludables.

Guía de estilo del equipo

Define y documenta una guía de estilo para tu equipo. La consistencia es más importante que la elección específica de cada convención.

Coding Standards

T-SQL
-- MAL formateado
select * from customers where customerid=1 and status='active';

-- BIEN formateado
SELECT c.CustomerID,
       c.FirstName,
       c.LastName,
       c.Email
FROM dbo.Customers c
WHERE c.CustomerID = 1
  AND c.Status = 'Active'
ORDER BY c.LastName;

Reglas recomendadas:

  • Mayúsculas para palabras clave SQL (SELECT, FROM, WHERE, AND)
  • Minúsculas para objetos y columnas
  • Usar alias de tabla (prefijo corto: c, o)
  • Indentación consistente (2 o 4 espacios)
  • Esquematizar siempre (dbo.Tabla)
  • Terminar sentencias con ;

Error Handling

T-SQL
CREATE PROCEDURE dbo.usp_InsertOrder
    @CustomerID INT,
    @Total      DECIMAL(10,2)
AS
BEGIN
    BEGIN TRY
        BEGIN TRANSACTION;

        INSERT INTO dbo.Orders (CustomerID, Total, OrderDate)
        VALUES (@CustomerID, @Total, GETDATE());

        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        ROLLBACK TRANSACTION;

        DECLARE @ErrorMessage NVARCHAR(4000) = ERROR_MESSAGE();
        DECLARE @ErrorSeverity INT = ERROR_SEVERITY();
        DECLARE @ErrorState INT = ERROR_STATE();

        RAISERROR(@ErrorMessage, @ErrorSeverity, @ErrorState);
    END CATCH
END;

Control de Versiones para Bases de Datos

Las bases de datos deben versionarse como el código. Usa migraciones (EF Core Migrations, Flyway, Liquibase, Alembic) para aplicar cambios de forma controlada y repetible.

Mantén un script init.sql con el esquema completo y scripts incrementales V001__description.sql con cada cambio.
